📊 The Problem: ROI Size Bias in Connectivity Comparisons

When comparing connectivity between ROIs of different sizes, larger ROIs naturally generate more streamlines simply because they contain more seed points. This creates a bias where connectivity appears higher for larger regions, even if the actual "connection density" is the same.

In this study: CTRL isocortex segments have ~900-1500 voxels each, while APTR graft segments have ~100-500 voxels. Raw streamline counts or SIFT2 sums would unfairly favor CTRL.

🔧 Available Solutions

Method Description Pros/Cons
1. Raw Streamline Count Count streamlines connecting ROI-A to ROI-B ❌ Only valid within-subject; heavily biased by ROI size
2. SIFT2 Weight Sum Sum of SIFT2 weights for all streamlines ✓ Valid cross-subject; ❌ Still biased by ROI size
3. Fixed Streamline Count Generate same number of streamlines per ROI ✓ Equal sampling; ❌ Undersamples large ROIs
4. Connectivity Density SIFT2_sum / ROI_voxels × 1000 ✓ Size-normalized; ✓ Valid cross-subject; ✓ Preserves SIFT2 benefits
5. Connection Probability Proportion of seeds that reach target ✓ Probabilistic interpretation; ❌ Loses quantitative aspect

✅ Chosen Solution: Connectivity Density

We use Connectivity Density as the primary metric:

Connectivity Density = SIFT2_sum / ROI_voxels × 1000

Why this approach?

  • Normalizes for ROI size: A 1000-voxel ROI and a 200-voxel ROI with equal "connection strength" will have equal density
  • Preserves SIFT2 benefits: Still accounts for FOD amplitude and enables valid cross-subject comparison
  • Interpretable units: "SIFT2 weight per 1000 voxels" is analogous to connection density per unit volume
  • Compatible with our design: CTRL (large atlas ROIs) and APTR (small manual ROIs) can be fairly compared

Note: FOD normalization (mtnormalise) was applied during preprocessing to enable valid between-subject comparisons.
